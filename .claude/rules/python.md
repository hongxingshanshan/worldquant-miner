# Python 文件规则

## 修改前必须读取
在编辑任何 Python 文件之前，必须先使用 Read 工具读取该文件的完整内容。

## 代码风格
- 使用 4 空格缩进
- 行长度不超过 120 字符
- 使用 snake_case 命名函数和变量
- 使用 PascalCase 命名类
- 常量使用 UPPER_SNAKE_CASE

## 导入顺序
1. 标准库（如 os, sys, json, logging）
2. 第三方库（如 requests, numpy）
3. 本地模块（如 .module 或 project.module）

每组导入之间空一行。

## 类型提示
- 所有公共函数应有类型提示
- 使用 typing 模块的类型（List, Dict, Optional, Callable）
- 返回类型明确标注

## 异常处理
- 使用具体的异常类型，不使用裸露的 `except:`
- 异常信息要具体，包含错误原因
- 关键异常必须记录日志
- 不静默吞掉异常

## 日志规范
- 使用 logging 模块，不使用 print
- 日志级别：DEBUG、INFO、WARNING、ERROR、CRITICAL
- 日志格式包含时间、级别、模块名、消息
- 不在日志中输出敏感信息

## 函数设计
- 单个函数只做一件事
- 函数名描述其行为
- 参数数量不超过 5 个，超过时考虑使用配置对象
- 有返回值的函数必须有类型提示

## 类设计
- 类名使用 PascalCase
- 相关功能组织在同一类中
- 使用 __init__ 初始化必要属性
- 私有方法使用 _ 前缀

## 文档字符串
- 公共函数和类必须有 docstring
- 使用三引号格式
- 描述功能、参数、返回值
- 不添加冗余注释

## 安全规范
- 不在代码中硬编码密钥、密码
- 使用环境变量或配置文件存储敏感信息
- API 调用使用 HTTPS
- 验证用户输入

## 性能规范
- 避免在循环中重复计算
- 使用生成器处理大数据
- 文件操作使用 with 语句
- 网络请求设置超时

## 测试规范
- 新功能添加对应测试
- 测试覆盖边界情况
- 测试名称描述测试场景
- 使用 pytest 或 unittest

## 进程和线程
- 子进程必须正确清理
- 使用 signal 处理退出信号
- 使用 atexit 注册清理函数
- 线程共享数据使用锁

## 代码修改检查清单
修改 Python 文件后，检查以下项目：
1. 语法是否正确（可使用 `python -m py_compile file.py`）
2. 导入是否完整且有序
3. 类型提示是否正确
4. 异常是否正确处理
5. 日志是否合理
6. 是否有敏感信息泄露风险
7. 是否需要更新相关测试
